# 原始资料字段映射与导入决策

2026-10-14 对四份参考文件做只读解析；以下仅记录结构和数量，不记录真实学生姓名或文本内容。

## 来源优先级

V1.1 签约学生项目管理总表为唯一可选的主导入源：5 条学生记录，120 条学生任务，4 组各 24 条模板。个案旧表有 1 条学生记录、24 条任务，均与 V1.1 对应内容重复且状态一致。V0.2 HTML 的 `SEED` 有 5 条学生和 120 条任务，均与 V1.1 对应内容重复且状态一致；浏览器中修改过的 `localStorage` 不包含在 HTML 文件中。早期 OS 工作簿的实际填充单元格只有表头，学生和任务记录数均为 0。

V1.1 状态分布：进行中 53、未开始 51、已完成 9、待触发 6、待确认 1。`待触发`、`待确认`保留原始值并设为待审核；此类任务即使意外设置家长可见，也不会出现在家长端，直到员工明确确认。跨来源去重键为学生标识加任务编号；预览报告只给出重叠数量、冲突编号和来源行号，不输出姓名。

## 学生与项目

| V1.1 字段 | 交付库 |
| --- | --- |
| 学生姓名 | `Student.name`；仅在私有数据库中 |
| 产品类型 | 归一化为本科、硕士、博士、硕博联申，写入 `Project.service_type` |
| 入学季 | `Project.intake_year` |
| 当前阶段 | `Project.current_phase` |
| 风险等级 | `Project.risk_level` |
| 项目状态 | `Project.source_status`，不擅自转换为内部状态 |
| 项目负责人、申请顾问、服务启动日、下一关键节点、当前核心问题、下一步动作 | 完整保留在 `Project.source_payload`，不根据姓名自动创建员工账号或公开给家长 |

学生原始工作表名、行号和文件名也写入 `Project.source_sheet/source_row/source_file`。家长授权在原始文件中不存在，必须人工设置。

## 学生任务

| V1.1 字段 | 交付库 |
| --- | --- |
| 学生姓名 + 模块编号 | 匹配项目 + `Task.source_code`，同项目编号唯一 |
| 任务名称、所属阶段 | `Task.name`, `Task.phase` |
| 实际负责人 | `Task.owner_label`；真实账号由管理员/员工另行绑定 `assignee_id` |
| 任务状态 | `Task.source_status` 保留原值；已完成、进行中、未开始可直接映射；待触发/待确认标记 `review_required` |
| 截止日期、风险等级 | `Task.due_date`, `Task.risk_level` |
| 标准负责人角色、计划开始日、实际完成日、是否需 Grace、当前问题、下一步动作、输出物链接、备注 | 完整保留在私有 `Task.source_payload`；备注另存 `internal_note` |

导入时所有 `Task.parent_visible` 为 `false`。来源文件名、工作表和行号写入任务；任何家长展示说明均需员工审核后设置。

## 模板

四张模板表的编号、任务名称、阶段、标准负责人角色映射到 `TemplateTask`。所有分类初始化为 `pending_review`。审核人员再选标准通用、条件触发或个案专属；只有标准通用会自动生成新项目任务。来源表含个案字段，不将它们直接当作标准模板。

## 异常处理

预览报告检查同源任务编号重复、同源学生重复、跨文件任务重叠、跨文件状态冲突。主导入还校验工作表结构、学生引用、产品类型、状态和 SHA-256；目标库已有学生或模板时拒绝隐式合并。整批导入在一个数据库事务中完成。后续有任务修改、授权或管理操作时自动回滚命令会拒绝执行。
